エージェントモードの GitHub Copilot は、コードベースを調べ、変更を提案し、ファイルを編集してコマンドを実行するなど、自律的に作業します。VS Code の Copilot Chat では、ツールの呼び出しやファイルの編集をリアルタイムで確認できます。エディターを離れずに差分を確認し、個々の変更を受け入れるか元に戻し、追加のプロンプトで作業を調整できます。

この演習では、次のことを行います。

- アクセシビリティエージェントの作業をリアルタイムで監視します。
- 提案されたファイルの編集を確認して受け入れます。
- 進行中のセッションで、高コントラストモードに加えてライトモードの切り替えを追加するようエージェントに依頼します。

## シナリオ

[演習 4][previous-lesson]で使ったアクセシビリティ用カスタムエージェントは、高コントラストモードを実装しています。作業中、デザインチームから追加の依頼がありました。既定のテーマが暗すぎると感じるユーザーのために、ライトモードも切り替えられるようにしたいとのことです。新しい会話を始める代わりに、現在のセッションに追加の作業を依頼します。

## Copilot の進行状況を監視する

Copilot Chat ビューには、エージェントが調べたファイル、実行したコマンド、提案した編集が表示されます。ファイルの編集は差分と **Keep** / **Undo** の操作とともにチャット内に表示されます。

1. 演習 4 で使った Copilot Chat ビューに戻ります。
2. エージェントの作業中にチャットをスクロールし、ツールの呼び出しを確認します。ファイルの読み取りや編集、実行を求めるターミナルコマンドが表示されます。
3. エージェントがファイルの編集を提案したら、チャット内に差分が表示されます。
   1. 変更を受け入れるには **Keep** を選択します。
   2. 変更を元に戻し、エージェントにもう一度作業させるには **Undo** を選択します。
4. チャット上部の **Files changed** を開くと、このセッション中にエージェントが変更したファイルの一覧を確認できます。

> [!NOTE]
> ターミナルコマンドの実行などでツールが許可を求める場合、エージェントは一時停止し、**Allow** の確認を表示します。
>
> 1. コマンドの内容を確認します。
> 2. 実行してもよいコマンドだけに **Allow** を選択します。

5. エージェントが高コントラストモードの実装を終えるまで待ちます。最後に、行った変更の概要が表示されます。

## ライトモードを追加するようエージェントに依頼する

高コントラストモードが実装されたら、同じ会話でライトモードの切り替えも追加します。会話を続けることで、エージェントは先ほどの作業、変更したコンポーネント、スタイルの方針、ローカルストレージの使い方を引き継げます。

1. Copilot Chat の入力欄に、ライトモードを同じユーザーインターフェイス (UI) の領域から操作できるように依頼する次の追加プロンプトを送信します。

   ```plaintext
   Nice work! Now add a light-mode toggle alongside the high-contrast toggle. Light mode should follow the same pattern — persist via local storage and be accessible from the same area of the UI. The user should be able to enable high-contrast and light mode independently.
   ```

2. エージェントが既存の変更を確認し、ライトモードの追加を提案することを確認します。
3. 高コントラストモードのときと同じように、新しい編集を確認し、各差分で **Keep** または **Undo** を選択します。
4. たとえば、望まない方向に進み、切り替え UI を意図しない形で再構成しようとした場合は、入力欄の横にある **Stop** を選択して停止し、意図を説明する追加メッセージを送信します。

> [!TIP]
> 作業中のセッションを方向付けると、最初からやり直すより早く調整できます。追加プロンプトでは、次のような依頼ができます。
>
> 1. 「Cascading Style Sheets (CSS) の変数を使って、重複するセレクターを避けてください」と伝え、スタイルを簡素化します。
> 2. 「3 つ目の切り替え項目は追加せず、既存の設定パネルにライトモードを組み込んでください」と伝え、意図する方向に修正します。
> 3. 「両方の切り替えにキーボードショートカットも追加してください」と伝え、作業範囲を広げます。

## 変更内容をレビューする

コミットする前に、エージェントが変更したファイルをまとめて確認します。

1. VS Code で **Source Control** ビューを開きます。
2. 変更されたファイルの一覧を確認します。Astro コンポーネント、スタイル、関連するテストが含まれていることがあります。
3. 変更されたファイルをいくつか開き、差分を確認します。アクセシビリティ用カスタムエージェントの指針に沿って、Accessible Rich Internet Applications (ARIA) 属性、キーボード操作、セマンティックな HyperText Markup Language (HTML)、ローカルストレージによる設定の保持が実装されていることを確認します。
4. 内容に問題がなければ、Source Control ビューで変更をステージしてコミットします。変更は[次のレッスン][next-lesson]で公開します。

## まとめと次のステップ

Copilot Chat のエージェントモードで、進行中の作業を監視し、ファイルの編集を確認して受け入れるか元に戻し、コンテキストを保ったまま追加プロンプトで作業を広げました。

この演習では、次のことを行いました。

- エージェントの作業をリアルタイムで監視しました。
- 個々のファイル編集を受け入れるか元に戻しました。
- セッションの途中で追加の指示を送り、エージェントの作業を調整しました。

次は、アクセシビリティ機能の作業をプルリクエストとして公開し、このラボでローカルのカスタムエージェントが行った変更をレビューします。
